# 0006. Языковые сервисы и LSP-клиент

**Дата:** 2026-11-05. **Статус:** принято владельцем.

## Контекст

Этап 4: диагностики, hover, автодополнение, переход к определению, инлайн-подсказки и code lens через языковые серверы. Нужны типы протокола, транспорт без tokio, долгоживущие процессы с пониженным приоритетом и синхронизация правок по изменённым диапазонам.

## Решение

- Зависимости `lsp-types` (0.97, MIT) и `serde_json` (MIT OR Apache-2.0) согласованы. `lsp-types` используется только в `lsp` и языковых пакетах. UI работает со своими типами крейта `language` (`LanguageService`, `Diagnostic`, `Hover`, …), чтобы плагины могли давать языковую поддержку без LSP.
- У каждого сервера три потока: чтение, запись, stderr. Запросы ждут ответа через `futures::channel::oneshot`. Если будущий результат запроса уничтожен, клиент шлёт `$/cancelRequest`.
- Кодировка позиций согласуется, предпочитается `utf-8`. Иначе позиции переводятся в utf-16 в потоке записи по снимку rope.
- `process::ProcessRunner::spawn` запускает долгоживущие процессы. Пониженный приоритет: на Windows флаг `BELOW_NORMAL_PRIORITY_CLASS`, на Unix `nice -n 10`, без `unsafe`.
- В `text::TextEdit` добавлен вставленный текст (`inserted`). Без него нельзя отправить несколько правок одного шага.
- rust-analyzer ищется по настройке `[rust_analyzer] path`, по умолчанию `rust-analyzer` из PATH. Автозагрузки нет.
- Hover, список дополнений, подчёркивания диагностик и панель Problems собраны из токенов, в макетах их нет. Цвета диагностик производные и ждут согласования.
- Один сервер на пару (язык, корень папки), общий для всех окон. Без открытой папки сервер не запускается.

## Последствия

- `TextEdit` больше не `Copy`: правки клонируются.
- Сниппеты в дополнениях (`snippetSupport`) отложены, это отдельный пункт ROADMAP.
