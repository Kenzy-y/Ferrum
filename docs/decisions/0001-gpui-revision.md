# 0001. Версия GPUI и gpui-component

**Дата:** 2026-11-04. **Статус:** принято.

## Контекст

AGENTS.md требовал подключать GPUI как git-зависимость с закреплённой ревизией, совместимой с gpui-component. Последний gpui-component — 0.9.0 (02.11.2026, репозиторий `longbridge/gpui-kit`). Он берёт GPUI не из git, а из crates.io: пакет `gpui-pre =0.3.11`. Это еженедельный снимок GPUI из Zed (коммит `zed@f816e1f`), который публикует сопровождающий gpui-component. Если подключить GPUI из git, в графе окажутся два разных GPUI, и gpui-component с ними не соберётся.

## Решение

- `gpui = { package = "gpui-pre", version = "=0.3.11" }`, `gpui_platform = { package = "gpui-pre-platform", version = "=0.3.11" }`, `gpui-component = "=0.9.0"`. Все версии точные, `Cargo.lock` в репозитории.
- Версии GPUI и gpui-component обновляются только вместе, отдельной задачей и отдельным коммитом. Перед обновлением нужно взять из `Cargo.toml` новой версии gpui-component точную версию `gpui-pre`, которую она требует.
- Toolchain в `rust-toolchain.toml` совпадает с версией Rust из `rust-toolchain.toml` Zed на коммите снимка (для `zed@f816e1f` это 1.98.1): платформенные крейты GPUI могут использовать только что стабилизированные API. На 1.97.0 не собирался `gpui-pre-macos`.
- В AGENTS.md (раздел 2) строка про GPUI изменена соответственно.

## Последствия

- Обновления GPUI выходят примерно раз в неделю, но зависят от сопровождающего gpui-component.
- Сборка воспроизводима: зависимости только с crates.io, без git.
- Если понадобится свежий GPUI раньше снимка, придётся подменять пакет через `[patch]`. Это будет отдельное решение.
